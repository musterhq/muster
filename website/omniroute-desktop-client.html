omniroute · routers

A desktop client for OmniRoute and other OpenAI-compatible routers

OmniRoute puts many model providers behind one OpenAI-compatible endpoint. Muster Agent is a free, open-source desktop app that connects to it as a first-class provider, lists its models and routes, and lets chats on those routes read files, edit code and run commands.

The setup

One endpoint in front, any model behind it.

A router such as OmniRoute lets you keep one address and one key while it decides which upstream provider answers, and it can publish named combos or automatic routes on top of individual models. That is convenient for coding agents, provided the client understands routers rather than treating them as a single model. Muster Agent does. It is independent of OmniRoute and works with any OpenAI-compatible router, gateway, Ollama or LM Studio.

Connecting

Add OmniRoute in a few clicks.

In Settings, open Accounts and providers, then Add provider. The screen shows one card per provider with a status chip. Ollama, LM Studio, OmniRoute and Custom endpoint start with their default address and an optional key. Choose OmniRoute, confirm the address, press Test connection, then Save. The name, base URL and key variable are under Advanced.

If your router is already configured in a local agent command-line tool, Muster Agent usually detects it on first launch and you do not need to add anything.

Models and routes, straight from the router

Muster Agent reads models from the router’s own model list instead of a hard-coded catalogue, so new models and combos appear without an app update. Routers that publish their own agents and automatic routes are shown as such. Sending waits for a router’s model list rather than reporting the model as unavailable. The last good list is remembered across restarts, failed listings retry on their own, and errors say exactly what is wrong.

The API key is actually sent

The key you paste is attached to every chat request. An earlier release sent chats without it and failed with HTTP 401; that was fixed, and it is covered by tests.

Agent tools

Routes can do real work, within the access you grant.

A chat on a local OpenAI-compatible route is not limited to conversation. It offers the tools the chat’s access level allows: read and list files, edit files inside the project folder, and, with Full access, run commands. These tools never follow a link out of the folder, end everything a command started when you press Stop, and run with a scrubbed environment so no keys or tokens leak into the command.

If a route refuses tools, the chat answers as plain chat and says so. A chat on a model that cannot run commands shows a notice, “This model can’t run commands or edit files”, with a one-click switch to a route that can, and the earlier conversation is carried over. A chat is never moved to another provider on its own.

Why use a router with a desktop client

  • One key to rotate. Change upstream providers behind the router without touching the app.
  • Per-chat choice. Use a cheap route for routine edits and a stronger one for hard problems.
  • Same workbench. Live diffs, terminal, memory and sandboxes work the same on a router route as on any other engine.

Muster Agent also runs Claude Code and Codex directly; see Run Claude Code and Codex in one app. Memory carries across all of them: long-term memory.
