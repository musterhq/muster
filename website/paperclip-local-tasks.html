paperclip · local work

Work locally on Paperclip tasks with Muster Agent

Paperclip plans the work and assigns it to agents and people. Muster Agent lets you pick a task up on your own computer, work in your own folders with the engine you choose, and send back a local work log with files changed, tests, tokens and cost.

The idea

Plan on the server, do the work on your machine.

Paperclip is an open-source orchestration server where agents and people share projects, tasks, approvals and budgets. Some of that work needs your own repository, your own tools and your own review, which a server-side agent cannot reach. Muster Agent connects to your Paperclip server so those tasks can be done locally and reported back in the place the rest of the team already looks.

Muster Agent and Paperclip are independent projects. Muster Agent does not replace Paperclip; it is a desktop client for it.

Connect and work

From connection to a checked-out task.

1. Connect a server

Open Settings, then Integrations, then Muster Server, type the server address and press Connect. A Paperclip running on this computer is offered inline, and an API token is available under other ways to connect. The app works out what is at the address by itself. Test connection says when a URL is not a Paperclip API and warns when a token would travel over plain http.

2. See the org in the app

Each Paperclip project appears under its organisation in the sidebar. Tasks open as conversation threads, and the Roster shows each agent with the adapter and model the server reports. The Inbox gathers questions, approvals and mentions. Paperclip and your own projects stay apart: an import never writes into a project you created in Muster Agent, and what you change locally is kept when you import again.

3. Work locally

Choose Work locally on a task to check it out. Muster Agent uses Paperclip’s ordinary primitives: it reassigns the task to you, posts comments and writes documents, so the state is visible in Paperclip itself. A Work as option maps a server agent’s model to the closest one you have locally and tells you when it differs, for example Opus on the server becoming Claude Code with Opus here.

4. Hand it back with a receipt

When you are done, the task gets a Local work log: files added and removed, tests, tokens, model and cost. You can also change priority and assignee from the task’s properties, create tasks with labels, goals and blockers, and approve, reject or ask for changes on Paperclip approvals. Nothing is sent until you press a button.

Optional plugin

Make check-outs visible inside Paperclip.

A small optional plugin, Muster for Paperclip, adds to Paperclip’s own web interface:

  • a Muster tab on each task showing who has it checked out, on which computer, since when, and the latest work summary, with an Open in Muster button;
  • a Receipts tab that renders the Local work log as a table with totals;
  • a My work page and sidebar link grouping your active tasks by project;
  • one reminder comment when a check-out has been quiet for a set number of hours (24 by default).

The plugin never reassigns anything, makes no outbound network calls and stores nothing of its own. Check-out works without it. It needs a self-hosted Paperclip and an instance admin to install it, and it cannot be installed on cloud-managed instances that only allow plugins baked into the platform image.

Who this suits

Teams that already plan in Paperclip and want engineers to use a real desktop workbench, with diffs, a terminal, memory and sandboxes, for the tasks that need local access. See long-term memory for how decisions carry across tasks, and running Claude Code and Codex together for engine choice.
